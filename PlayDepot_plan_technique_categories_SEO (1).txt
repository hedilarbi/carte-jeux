1. Architecture des nouvelles URLs
Les pages de catégories actuellement ouvertes avec /produits?q=... doivent être remplacées par des routes stables. Cette architecture permet d’attribuer un Title, un H1, une introduction, une FAQ et un canonical uniques à chaque catégorie réellement stratégique.
Famille
Structure cible
Exemple
Plateformes
/categories/plateformes/[slug]/
/categories/plateformes/steam/
Types
/categories/types/[slug]/
/categories/types/cartes-prepayees/

Règle SEO  Créer techniquement toutes les routes ne signifie pas indexer automatiquement les 100 catégories. Le champ indexable doit être administrable. Les catégories faibles restent en noindex,follow et hors sitemap.

4. Règles d’indexation des catégories
Une catégorie devient indexable uniquement si elle possède une intention de recherche identifiable et suffisamment de contenu ou de produits. Les conditions doivent être centralisées dans l’administration.
Produits actifs et disponibles.
Intention de recherche identifiable.
H1, Title et meta description spécifiques.
Introduction unique et utile.
Canonical auto-référent.
Maillage interne depuis /categories, la home ou les pages produits.
Absence de duplication avec une autre catégorie.
Les catégories de classement interne telles que random-try-to-get, other-randoms, meetup-2019 ou the-real-steam-bangers peuvent exister, mais doivent rester en noindex,follow et ne pas apparaître dans le sitemap.
5. Actions à fournir à Hedi
5.1 Créer les routes catégories
Créer /categories/plateformes/[slug]/.
Créer /categories/types/[slug]/.
Récupérer automatiquement les produits associés au slug.
Ajouter les champs admin : indexable, seoTitle, metaDescription, h1, intro, canonical et updatedAt.
Rendre le canonical auto-référent pour toute catégorie indexable.
Appliquer noindex,follow aux catégories non validées.
Modifier toutes les cartes de /categories afin qu’elles pointent vers les URLs propres.
Supprimer les liens de catégorie construits avec ?q=.
5.2 Rediriger les anciennes catégories
Chaque ancienne URL ?q= correspondant à une catégorie doit recevoir une redirection 301 côté serveur vers sa nouvelle URL. Les redirections JavaScript seules ne sont pas suffisantes.
/produits?q=psn
→ 301 → /categories/plateformes/psn/
 
/produits?q=steam
→ 301 → /categories/plateformes/steam/
 
/produits?q=free-fire
→ 301 → /categories/types/free-fire/
 
/produits?q=cartes-prepayees
→ 301 → /categories/types/cartes-prepayees/

5.3 Corriger les filtres
Une catégorie permanente utilise une URL propre.
Un filtre temporaire ne crée aucune URL.
Conserver les sélections dans l’état React.
Ne pas utiliser router.push() ou router.replace() pour les filtres.
Ne pas rendre de <Link href="?..."> ou de formulaire GET.
Charger les résultats par appel API.
Dédupliquer les paramètres sélectionnés.
Ne plus rendre de liens contenant platform, type, region, search, page ou limit.
Retourner 404 ou 410 pour une pagination impossible, jamais 500.
5.4 Traiter les anciennes facettes
Les anciennes URLs de filtres qui ne correspondent pas à une catégorie propre restent temporairement accessibles avec noindex,follow afin que Google puisse constater leur retrait de l’index.
<meta name="robots" content="noindex,follow">
<link rel="canonical" href="https://playsdepot.com/produits">

Sont concernés : platform, type, region, search, page et limit. Les combinaisons invalides ou répétées doivent retourner 404 ou 410.
6. robots.txt
6.1 Version à publier immédiatement
Cette version déclare le sitemap et laisse Google revisiter les anciennes facettes pour lire leur noindex.
User-agent: *
Disallow: /api/
 
Sitemap: https://playsdepot.com/sitemap.xml

6.2 Version finale après désindexation
User-agent: *
 
Disallow: /api/
Disallow: /*?*platform=
Disallow: /*?*type=
Disallow: /*?*region=
Disallow: /*?*search=
Disallow: /*?*page=
Disallow: /*?*limit=
 
Sitemap: https://playsdepot.com/sitemap.xml

Attention  Ne pas bloquer /_next/. Ne pas activer les Disallow des paramètres avant que Google ait pu lire les noindex et retirer les anciennes URLs.

7. Sitemap XML dynamique
7.1 URLs à inclure
Accueil, /produits et /categories.
Catégories avec active=true et indexable=true.
Fiches produit actives et indexables.
Pages éditoriales canoniques en 200.
7.2 URLs à exclure
Toute URL contenant ?.
Catégories noindex.
Pages redirigées, 404 ou 500.
Panier, checkout, connexion, inscription et favoris.
Recherche interne, /api/ et /_next/.
7.3 Exemple Next.js - app/sitemap.ts
import type { MetadataRoute } from "next";
import { db } from "@/lib/db";
 
const DOMAIN = "https://playsdepot.com";
 
export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const [products, categories] = await Promise.all([
    db.product.findMany({
      where: { active: true, indexable: true },
      select: { slug: true, updatedAt: true },
    }),
    db.category.findMany({
      where: { active: true, indexable: true },
      select: { slug: true, family: true, updatedAt: true },
    }),
  ]);
 
  return [
    { url: `${DOMAIN}/`, lastModified: new Date(), priority: 1 },
    { url: `${DOMAIN}/produits`, lastModified: new Date(), priority: 0.9 },
    { url: `${DOMAIN}/categories`, lastModified: new Date(), priority: 0.8 },
    ...categories.map((category) => ({
      url: `${DOMAIN}/categories/${category.family}/${category.slug}/`,
      lastModified: category.updatedAt,
      priority: 0.8,
    })),
    ...products.map((product) => ({
      url: `${DOMAIN}/produits/${product.slug}`,
      lastModified: product.updatedAt,
      priority: 0.7,
    })),
  ];
}

Au-delà de 50 000 URLs ou 50 Mo non compressés, répartir les produits dans plusieurs sitemaps et créer un index sitemap.
8. Markup FAQPage
Le balisage doit refléter une FAQ réellement visible sur la page. Les questions et réponses doivent être spécifiques à la catégorie ; il ne faut pas injecter la même FAQ sur toutes les pages. Pour un site e-commerce, l’affichage d’un résultat enrichi FAQ n’est pas garanti.
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "@id": "https://playsdepot.com/categories/plateformes/steam/#faq",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Comment acheter une carte Steam en Tunisie ?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Choisissez la carte Steam correspondant au montant et à la région souhaités, ajoutez-la au panier et payez avec l’un des moyens de paiement proposés en dinars tunisiens. Le code est transmis après validation du paiement."
      }
    },
    {
      "@type": "Question",
      "name": "Les cartes Steam fonctionnent-elles avec un compte tunisien ?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "La compatibilité dépend de la région indiquée sur la fiche produit. Sélectionnez une carte compatible avec la région configurée sur votre compte Steam."
      }
    },
    {
      "@type": "Question",
      "name": "Comment activer un code Steam ?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Connectez-vous à Steam, ouvrez le menu Jeux, sélectionnez Activer un produit sur Steam puis saisissez le code reçu."
      }
    }
  ]
}
</script>

Générer dynamiquement @id, questions et réponses.
Le texte du markup doit être identique au contenu visible.
Ne pas ajouter de questions absentes de la page.
Tester la syntaxe avant le déploiement global.
9. Markup Product
Ce balisage s’applique uniquement aux fiches produit individuelles. Les données doivent correspondre exactement au prix, au stock, à l’image et au produit visibles sur la page.
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "@id": "https://playsdepot.com/produits/carte-steam-50-eur-global#product",
  "name": "Carte Steam 50 EUR - Global",
  "description": "Carte cadeau Steam de 50 EUR permettant d’ajouter du crédit au portefeuille Steam. Vérifiez la région avant l’achat.",
  "image": [
    "https://playsdepot.com/images/products/carte-steam-50-eur-global.webp"
  ],
  "url": "https://playsdepot.com/produits/carte-steam-50-eur-global",
  "sku": "STEAM-50-EUR-GL",
  "category": "Cartes Steam",
  "brand": {
    "@type": "Brand",
    "name": "Steam"
  },
  "offers": {
    "@type": "Offer",
    "url": "https://playsdepot.com/produits/carte-steam-50-eur-global",
    "priceCurrency": "TND",
    "price": "175.00",
    "availability": "https://schema.org/InStock",
    "itemCondition": "https://schema.org/NewCondition",
    "seller": {
      "@type": "Organization",
      "name": "PlayDepot",
      "url": "https://playsdepot.com/"
    }
  }
}
</script>

9.1 Champs dynamiques obligatoires
@id, name, description, image et url.
sku, category et brand.name.
offers.url, priceCurrency, price et availability.
const availability = product.inStock
  ? "https://schema.org/InStock"
  : "https://schema.org/OutOfStock";

9.2 Règles Product
N°
Exigence
1
Utiliser TND, jamais DT ou DTN.
2
Le prix JSON-LD doit être identique au prix visible.
3
La disponibilité doit provenir du stock réel.
4
Ne jamais inventer une note ou des avis.
5
Ajouter aggregateRating uniquement si les avis sont réels et visibles.
6
Conserver une seule URL canonique par produit.
7
Tester plusieurs fiches avec le Rich Results Test avant le déploiement global.
